# Rust native callbacks

The Rust backend transports supported function values through the C runtime’s real closure header. Signature-specific C and Rust thunks carry arguments and results; the Sindarin body continues to execute as Rust. Headers use C allocation, reference credits and cleanup callbacks. Registries preserve identity when handles are retained, returned, copied or passed back across the boundary. Nil function values remain null headers.

Scalar and pointer signatures, strings, supported value records and canonical arrays have executable coverage. Arrays retain the actual C header, element width, copy and release callbacks. Character elements occupy one byte; string elements own C pointers. Record arrays check size, alignment and field offsets against C. Nested arrays own inner C headers, and mutable indexed operations borrow the actual inner allocation. Owned results and value copies acquire independent storage.

String element views retain their array or callback cell owner through the native call. The bridge releases RefCell borrows before reentry. Declaration and expression-statement indexed temporaries follow the C emitter’s enclosing-scope lifetime. Character reference storage and native record string fields preserve their real addresses. Joined-thread tests cover callback transport and retained identity; a C credit gate serializes closure reference updates in generated native translation units.

The permanent gate contains 68 sources and 612 optimization/arithmetic comparisons. It checks literal outputs and frozen source/helper hashes, including unchanged original interop programs. Linux lifetime checks exercise 204 cases per backend; the Rust run instruments native C objects with Clang while using Rust’s ASAN runtime for the final executable. The worker uses an existing project-local Clang through `SN_NATIVE_CALLBACK_SAN_CC`; CI requires its existing Clang. No compiler or sanitizer installation occurs in the test script.

Run `make test-rust-parity-native-callbacks`, `python3 scripts/check_c_native_callback_lifetimes.py`, and `python3 scripts/check_rust_native_callback_lifetimes.py`. The mode gate runs on Linux, macOS and Windows. Passing one gate does not establish full backend parity.

Remaining work includes wider qualified callback signatures, reentry through threaded array owners, native-library credits compiled without the generated gate, userdata aliasing and concurrent native buffer writes, additional field/temporary owners, and unsupported record/interface layouts. Borrowed method-self captures, interface identity and native record references combined with captured scalar field owners remain full-goal gaps. Rejected or C-undefined probes are excluded from completed parity. C remains the default target.
